จุดหมาย ABCD ตามป้ายใหม่

A · โซนกู้ภัย (Rescue Zone) — มุมล่างซ้าย

B · โซนการแพทย์ (Medical Zone) — มุมบนซ้าย

C · โซนส่งเสบียง (Supply Zone) — มุมบนขวา

D · ศูนย์บัญชาการ (Command Center) — มุมล่างขวา

กลับจุดเริ่มต้น, Staff Return และ Auto-return เป็น D ศูนย์บัญชาการ ส่วนไปจุด A ยังเป็นโซนกู้ภัย ฝั่ง Robot เป็นผู้เก็บพิกัดและต้อง deploy ABCD บน Pi ก่อนเดินจริง

เปิดระบบตามปกติ

  1. ให้ฝั่งหุ่นเปิด VM, Tailscale, Discovery Server, Robot Bridge และ Nav2 ก่อน
  2. เปิด Tailscale ภายใน Ubuntu WSL ตามการตั้งค่าชุดนี้ แล้วใช้คำสั่ง Backend ด้านล่างเพียง terminal เดียว
  3. เข้า Staff แล้วตรวจ Process, ROS และอายุข้อมูล Robot แยกกัน Backend จะเปิด Intent/Subtitle ให้ หากไม่ได้ค้างอยู่ใน Manual หรือเคยสั่งปิด node ไว้
  4. หากต้องการโหมดคุย ให้กดอ่านโหมด Subtitle แล้วเลือก Friendly หลังเปิดหรือ Restart Subtitle

Terminal Backend

cd ~/ros2_ws/Mobile-Web-Voice-Text-Controller-Physical-and-Immersive-AI-
bash booth_web_controller/run_tailscale.sh

คำสั่งนี้ใช้กับรุ่นที่มีตัวดูแล process และ LLM ที่ build แล้ว ไม่ต้องเปิด Intent/Subtitle ซ้ำ หากยังไม่ได้ build หลังอัปเดต ให้ดูหัวข้อคำสั่งตรวจเพิ่มเติมท้ายคู่มือ

Static QR และ Cloudflare Tunnel

เปิดการทำงานอัตโนมัติโดยตั้ง ENABLE_TUNNEL=true ในไฟล์ booth_web_controller/.env พร้อมตั้ง Worker URL, API token, Account ID และ KV namespace ID จากนั้นเปิด Backend ตามปกติ ค่าเริ่มต้นคือปิด

สถานะ Process ทำงานอยู่หมายถึงโปรแกรม cloudflared ยังทำงาน ไม่ได้ยืนยันว่า Tunnel เชื่อมต่อได้ ต้องดู Target reachable แยกกัน URL กลางคัดลอกได้จากช่องสถานะ Tunnel เมื่อเปิดใช้งาน

หากไม่ใช้ระบบอัตโนมัติ ให้เปิด Quick Tunnel ใน terminal ด้วย cloudflared tunnel --url http://127.0.0.1:8000 แล้วนำ URL ที่ได้ไปอัปเดตค่า robot_url ใน Worker KV ผ่าน Wrangler หรือ Dashboard โดยตรวจให้เป็น HTTPS subdomain ของ trycloudflare.com ก่อน

เมื่อปิด Backend ตามปกติ manager จะหยุดเฉพาะ cloudflared ที่เปิดเอง ค่า KV จะไม่ถูกลบ หากเปิด tunnel เอง ให้หยุดจาก terminal เจ้าของด้วย Ctrl+C ห้ามใช้ pkill cloudflared

คำสั่ง fallback สำหรับอัปเดต KV

cd cloudflare/robot-link
npx wrangler kv key put robot_url 'https://<quick-tunnel>.trycloudflare.com/' --namespace-id '<KV_NAMESPACE_ID>'

เห็นอาการนี้ ควรตรวจตรงไหน

อาการตรวจและทำต่อ
Tailscale ไม่เชื่อม / VM ping ไม่ได้ดูสถานะ local กับ VM แยกกัน ให้ฝั่ง VM ตรวจว่าเครื่องและ Tailscale เปิดอยู่ Online ที่ peer รายงานยังไม่ยืนยันว่า ping หรือ DDS ติดต่อได้
Process ล้มเหลวเปิด Log ของ node นั้น ดู exit code และข้อผิดพลาด เช่น key ไม่พร้อม, venv หาย หรือยังไม่ได้ build แก้ต้นเหตุก่อนกดเปิดใหม่ ไม่ต้องแสดง API key ให้ผู้อื่นดู
Process อยู่ แต่ ROS ไม่ตอบตรวจ domain และ Discovery Server ให้ตรงกัน ตรวจ VM/Discovery ก่อน หากเพิ่งกลับจาก VM ออฟไลน์ ให้ Restart node ที่ไม่ตอบแล้วตรวจใหม่ การเห็นชื่อใน graph อย่างเดียวไม่ยืนยันว่าติดต่อได้
Robot NOT_READY / ไม่มีสถานะสดดูอายุ stamp ต้นทางและเวลารับล่าสุด ถ้าข้อมูลสดแต่ไม่พร้อม ให้ฝั่งหุ่นตรวจ Robot Bridge/Nav2 การ Restart Intent ไม่ทำให้หุ่นพร้อมโดยอัตโนมัติ
ซับเก่าค้าง / ซับไม่เปลี่ยนเว็บกับ VR ตั้งใจเก็บซับล่าสุดไว้ ดูรหัสคำสั่ง ผล Intent และเวลา/ลำดับซับใหม่ประกอบ ตรวจ ROS ของ Subtitle, log และนาฬิกาต้นทางก่อน Restart
VR เชื่อมต่อ 0 ตัวตรวจ URL และเส้นทางจากอุปกรณ์ VR ไป Backend ใช้ /ws/vr/subtitle บน Backend ที่ถูกตัว 127.0.0.1 บน Quest หมายถึง Quest เอง ต้องใช้ IP Backend ที่อุปกรณ์เข้าถึงได้
VR เชื่อมแล้ว แต่ไม่เห็นซับเทียบเวลาส่งและลำดับล่าสุดกับข้อความใหม่ การส่งสำเร็จยังไม่ยืนยันการแสดงบนจอ ให้ตรวจ receiver, Target และฟอนต์ฝั่ง Unity ร่วมด้วย
ปุ่มเปิด node ถูกปิดไว้ถ้าเป็น Mock ระบบจะไม่เปิด ROS จริง ถ้าเป็น Manual ให้ใช้ terminal หรือกลับ Automatic ถ้าปิดตัวดูแลด้วย MANAGE_AGENT_NODES=false ต้องเปิด Backend ใหม่แบบปกติก่อนใช้ปุ่ม
พบ process ภายนอกตัวดูแลไม่ปิด process ที่เปิดเอง ให้กลับไปกด Ctrl+C ใน terminal เจ้าของตัวนั้นก่อนใช้ Automatic อย่าใช้ pkill python เพื่อแก้ปัญหา
หน้าเว็บค้าง / Backend ตายใช้ stop-all หรือ kill-all ด้านล่างได้โดยไม่ใช้ HTTP/ROS แล้วกลับไปเปิด node ทีละ terminal หากเปิดหน้าเว็บไม่ได้เลย ให้เปิด README หลักของ branch นี้แทน

Fallback กลับไปเปิดเองใน terminal

ปิด node ไม่ใช่ Emergency Stop และไม่ยืนยันว่าหุ่นหยุดเดิน หากต้องการหยุดการเคลื่อนที่ ให้ใช้ปุ่มหยุดฉุกเฉินด้านบนหรือประสานฝั่งหุ่นก่อน

  1. ถ้าหน้า Staff ยังทำงาน กด Manual เพื่อปิด process ที่ Backend ดูแลและจำว่าไม่ให้เปิดกลับเอง
  2. หาก UI ใช้ไม่ได้ ใช้ stop-all ด้านล่างจากบัญชี Linux เดียวกับ Backend ระบุ workspace เดียวกัน คำสั่งจะบันทึก Manual ก่อนปิด และบังคับปิดเมื่อรอแล้วไม่จบ
  3. เปิด Intent กับ Subtitle ในคนละ terminal ด้วยคำสั่งเดิม เปิด Backend แบบไม่ดูแล node ตามคำสั่งด้านล่างหากต้องเปิดเว็บใหม่

ดู process ที่ตัวดูแลเปิด

python3 booth_web_controller/tools/agent_nodes.py status --workspace ~/ros2_ws/turtlebot-llm

ปิดทั้งหมดและเข้า Manual

python3 booth_web_controller/tools/agent_nodes.py stop-all --workspace ~/ros2_ws/turtlebot-llm
ต้องการบังคับปิดทันที (Kill)

Kill เฉพาะ process ที่ตัวดูแลเปิด

python3 booth_web_controller/tools/agent_nodes.py kill-all --workspace ~/ros2_ws/turtlebot-llm

คำสั่ง fallback ตรวจตัวตน process ก่อนปิด ไม่แตะตัวที่เปิดจาก terminal เอง และไม่เปิด node กลับจนสั่งเปิดหรือออกจาก Manual

Terminal 1 · Intent

cd ~/ros2_ws/turtlebot-llm
bash ./run_tailscale.sh intent

Terminal 2 · Subtitle

cd ~/ros2_ws/turtlebot-llm
bash ./run_tailscale.sh subtitle

Terminal 3 · Backend แบบเปิด node เอง

MANAGE_AGENT_NODES=false bash booth_web_controller/run_tailscale.sh

กลับมาใช้ Automatic

  1. กด Ctrl+C ใน terminal ที่เปิด Intent และ Subtitle เองให้ปิดก่อน เพื่อไม่ให้มีตัวซ้ำ
  2. ถ้า Backend เปิดตัวดูแลไว้ กด Automatic ในแท็บควบคุม แล้วตรวจ Process กับ ROS อีกครั้ง
  3. ถ้าเปิด Backend แบบ MANAGE_AGENT_NODES=false ให้หยุด Backend ตัวนั้น จากนั้นใช้คำสั่งเตรียมโหมดและเปิดใหม่ด้านล่าง

เตรียม Automatic แล้วเปิด Backend ใหม่

python3 booth_web_controller/tools/agent_nodes.py automatic --workspace ~/ros2_ws/turtlebot-llm
bash booth_web_controller/run_tailscale.sh
